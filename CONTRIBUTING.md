# Contributing to agda-groups

Thank you for your interest in agda-groups.  This guide says how a
contribution is checked, how a module joins the library, how its types
are stated over the library's finite groups and subgroups, and what
happens to a pull request once it is opened.  The [README](README.md)
says what the library holds and how it is checked; read it first.

## Before you start

+  **Open an issue first** for anything larger than a small correction: a
   new module, a new statement, a change to the type of a statement, or a
   change to the checks.  The plan,
   [`docs/GITHUB_PROJECT.md`](docs/GITHUB_PROJECT.md), lists the issues
   the library is built from; the issue lets the maintainer say where the
   work fits, or whether it is already under way, before you invest in it.
+  **A correction to a module** (a wrong citation, a misleading sentence,
   a proof that could be shorter) is welcome as an issue alone; a pull
   request is welcome too.
+  **A design decision** (a new representation, or a change to one
   below) is recorded as an ADR under [`docs/adr/`](docs/adr/) before the
   code that rests on it.
+  **Licensing**.  The library is licensed under the Apache License 2.0
   (`LICENSE`).  By its section 5, a contribution you submit is licensed
   under the same terms, unless you say otherwise in the pull request.

## The environment

The toolchain is the repository's [Nix][] flake, and nothing else is
needed: Nix 2.28 or later, with flakes enabled.  The README's section
"Checking the library" says how to fetch Agda from the public binary
cache instead of building it.

    git clone https://github.com/ualib/agda-groups.git
    cd agda-groups
    nix develop

`nix develop` pins Agda 2.9.0, the Agda standard library 2.4.1 and the
[Agda Universal Algebra Library][agda-algebras] at the commit `flake.lock`
names.  It writes a project-local Agda configuration under `.agda/`, a
wrapper, `.agda/bin/agda`, that runs the pinned Agda with that
configuration, and a writable copy of the pinned Agda Universal Algebra
Library under `.deps/`, so nothing in your own Agda configuration takes
part.  To check files from an editor, launch the editor from inside
`nix develop`, or point it at that wrapper.

## Checking a contribution

Run these from the repository's root, inside `nix develop` (or prefix
each with `nix develop --command`).

### `make check`

`make check` runs the options check (`make safety`,
`scripts/check-safety.sh`), generates the aggregator
`src/EverythingGroups.agda`, which imports every module under `src/`,
type-checks it with a heap limit of 6 GiB, and lints the plan
(`make lint`).  It exits 0 when every module checks.  On the library as
it stands it prints, apart from Agda's own progress lines, the following,
and then the lint's count of the plan's milestones, labels and issues,
with 0 errors and 0 warnings:

    bash scripts/check-safety.sh src agda-groups.agda-lib
    safety: 1 modules, each with the pragma and no postulate or unsafe pragma
    wrote src/EverythingGroups.agda (1 modules)
    agda +RTS -M6G -A128M -RTS  src/EverythingGroups.agda
    gh-project-lint docs/GITHUB_PROJECT.md

The aggregator is generated by `find`, so a new module is checked as soon
as its file is in the tree; there is no list to edit.  When a module first
imports a module of the Agda Universal Algebra Library, the next run also
checks that module and the modules it imports, and keeps their interfaces
under `.deps/agda-algebras/_build/`.

### `make check-lean`

`make check-lean` runs the options check, its cases (`make safety-test`,
`scripts/test-check-safety.sh`) and the plan's lint, with no Agda, in a
few seconds; `nix develop .#lean --command make check-lean` runs it in a
shell that fetches no Agda at all.  Run it whenever you change
`scripts/check-safety.sh`: a new rule of the check comes with a case that
passes, a case that fails, and the message the failure prints.

### CI

CI runs the plan's lint on every pull request.  The full `make check` and
`make check-lean` join it on every pull request and on `main` with M1-2
of the plan; until then, run both yourself before you open a pull
request.

## How a module joins the library

The rules below describe the modules a contributor writes; when in doubt,
follow the modules beside yours, and the modules of the Agda Universal
Algebra Library that yours imports.

### Name and place

+  A module's name is `Groups.` followed by its path under `src/Groups/`:
   `Groups.Subgroup.Generated` is `src/Groups/Subgroup/Generated.lagda.md`.
   ADR 0001's § 8 names the first modules, nested by topic.
+  **A published name is kept**.  Once a module or a definition is in a
   release, its name does not change silently.  To rename one, keep the
   old name beside the new for at least one release, with a warning:
   `{-# WARNING_ON_USAGE old-name "..." #-}` after the old definition, or,
   for a module, the old module re-exporting the new with
   `{-# WARNING_ON_IMPORT "..." #-}`.  Both pass `--safe` and the options
   check.  The same holds for a change to a published definition's type:
   add the new definition beside the old, and deprecate the old.

### The file

+  **Literate Markdown**.  Every module is a `.lagda.md` file: prose, with
   the code in fenced `agda` blocks between the paragraphs, and the prose
   says what the code defines and proves.  The options check refuses the
   other literate formats.
+  **Front matter**.  Every module opens with front matter of the
   following form, the form of the Agda Universal Algebra Library's
   modules, with the date the module was written; its first heading after
   it is a `###` heading naming the module's subject, and its first
   sentence says which module it is:

       ---
       layout: default
       file: "src/Groups/Subgroup/Generated.lagda.md"
       title: "Groups.Subgroup.Generated module"
       date: "2026-11-26"
       author: "the agda-groups development team"
       ---

       ### Subgroups given by generators

       This is the `Groups.Subgroup.Generated` module of the agda-groups library.

+  **The pragma**.  Every module's code begins with
   `{-# OPTIONS --without-K --exact-split --safe #-}`, its one `OPTIONS`
   pragma, ahead of its first declaration, and holds no `postulate` and no
   pragma that switches a check off (`TERMINATING`, `NO_POSITIVITY_CHECK`
   and the like).  No module adds `--lossy-unification`, which `--safe`
   accepts: the Agda Universal Algebra Library uses it nowhere, and a
   module that needs it is a decision to record in an issue first, not an
   edit.  `scripts/check-safety.sh` enforces all of this, and refuses a
   `flags` field in `agda-groups.agda-lib`.
+  **The header block**.  A module may put the pragma, the `module` line
   and the imports in one block of code inside an HTML comment (`<!--`
   and `-->` around the fence), so that the rendered page opens with
   prose, as the Agda Universal Algebra Library's modules do.
+  **Imports**.  Every `open import` names what it takes, in a `using`
   clause or by `renaming` (a module that only re-exports others uses
   `public`), grouped under the comments `-- Imports from the Agda
   Standard Library`, `-- Imports from the Agda Universal Algebra Library`
   and `-- Imports from this library`.

### Imported, never copied

The library is built on the group theory of the Agda Universal Algebra
Library (`Classical.Structures.Group` and its submodules,
`Classical.Bundles.Group`, `Setoid.Algebras.Finite` and the examples of
`Examples.Classical.Groups`), and on nothing else of ualib's.  Its modules
are imported, never copied or moved, since other libraries import them
too: a notion that library already defines (a subgroup, a coset, a
conjugate, a normal subgroup, a centralizer, Dedekind's law) is used
under its own name, not defined again.  The library does not depend on
agda-lattices.

### Definitions and proofs

+  **One lemma per idea**.  Prefer small named lemmas to long proofs: a
   lemma with a name says what a step of a proof is, and another proof can
   use it.
+  **A type signature on every definition** at the top level of a module,
   or of a named module inside it.  Only local abbreviations go without,
   such as the definitions of a `where` clause.
+  **Each definition is introduced**: by a line comment directly above
   it, or by name in the prose before its block.

### Stating and citing a result

+  **As a textbook states it**.  A theorem is stated in the form a
   textbook of finite group theory gives it, hypotheses and all, and is
   named as the textbook names it (Lagrange's theorem, the class
   equation, the Frattini argument).  A lemma of the proof that no
   textbook states is named for what it says.
+  **Aschbacher's number first**.  The main reference is M. Aschbacher,
   *Finite Group Theory*, 2nd ed. (Cambridge University Press, 2000).
   The library follows its order where it can, and a module cites
   Aschbacher's number for a result first, in his form: "Aschbacher
   (1.5)" for Lagrange's theorem, with the result's name where it has
   one.
+  **The other books beside it**: the books of the plan's
   [Sources](docs/GITHUB_PROJECT.md#sources), each by its own numbering:
   Gorenstein, *Finite Groups* ("Gorenstein 10.1.2", in his cross-chapter
   form); Isaacs, *Finite Group Theory* ("Isaacs X.3" for the results of
   its appendix, The Basics); Kurzweil and Stellmacher, *The Theory of
   Finite Groups*; and Rotman, *An Introduction to the Theory of Groups*.
   A book that does not state a result is not cited for it, and a number
   is read from the book, never from memory or from another citation.
   Cite any other source the same way, by the number of the result.

## Finite groups and their subgroups

Every type of the library is stated over one representation of a finite
group and of its subgroups, decided in
[ADR 0001](docs/adr/0001-finite-groups.md), which holds the evidence for
each rule below; its companion note,
[`finite-groups.md`](docs/notes/finite-groups.md), explains the design.
The rules, each with its reason, are as follows.

+  **A finite group carries its enumeration as data**.  A finite group is
   the Agda Universal Algebra Library's `Group` together with an
   `IrredundantEnumeration` of its carrier: an enumeration by `Fin n` that
   reaches every element, up to the group's equality, exactly once.  The
   order is the size of the enumeration, and the index map and the
   decidable equality are derived from it.  The reason: counting needs an
   enumeration, and the one that library derives by deduplication from a
   `FiniteAlgebra` witness is correct but slow to compute with, since its
   index map evaluates a proof at every lookup.  So give a concrete group
   its enumeration directly (the identity, for a group on `Fin n`), and
   never compute through the deduplicated one.
+  **A subgroup is a decidable subgroup**, that library's `DecSubgroup`:
   a predicate on the carrier, a proof that it is a subgroup, and a
   decision procedure for its membership.  The reason: a decision
   procedure is what lets a subgroup's order be counted and its
   inclusions be decided over the enumeration, and it is what keeps the
   second rule below from proving excluded middle.
+  **A subgroup is given by generators where it can be**, as GAP gives
   one: x lies in ⟨A⟩ when a word in A and its inverses evaluates to x.
   The reason: the textbook's description is then the definition, with
   its universal property (a subgroup that holds A holds ⟨A⟩), and
   inclusion, normalizers and conjugates are decided by testing the
   generators alone, which is far cheaper than testing every element.
+  **An equality of subgroups is `≐`, never `≡`** (the first rule).  Two
   subgroups are equal when they have the same elements, `H ≐ K`, the pair
   of inclusions H ⊆ K and K ⊆ H, which the enumeration decides.  The
   reason: under `--without-K --safe`, two subgroups with the same
   elements are not propositionally equal, so a statement with `≡`
   between subgroups cannot be proved, nor its hypothesis supplied, for
   any concrete group.
+  **A disjunction about every subgroup is stated only over decidable
   subgroups** (the second rule).  A statement may say that every
   decidable subgroup between H and K is H or K.  Where a statement
   quantifies over subgroups that are only predicates (as the Agda
   Universal Algebra Library's `MinimalNormal` does), it carries a
   witness instead: "a subgroup between H and K that holds an element
   outside H contains K".  The reason: for any proposition P, the
   predicate "x is 1, or P holds and x is in K" is a subgroup between 1
   and K, so a disjunction about every predicate subgroup proves P or not
   P; that subgroup is decidable only when P is, so the disjunction over
   decidable subgroups decides nothing new.  For a concrete group the
   disjunction is proved by the generator condition of ADR 0001's § 3.
+  **A certificate is held in a record, never in a type at a call**.  A
   generated subgroup's decision procedure is made fast by a certificate
   that Agda checks by evaluation; the record that holds it (`Generators`,
   and `Adjoined` for the subgroups ⟨x, B⟩) is what a function takes.  The
   reason: a certificate written in a type at a call is evaluated again
   wherever Agda compares that type with another spelling of it, and
   under a bound variable it is evaluated symbolically, which can exhaust
   the heap; a record is compared by name.  Solve a certificate's checks
   with `_` where the record is built.
+  **A decision procedure asked many questions is remembered by `memo`**.
   Agda does not remember what a function has answered, so a computation
   that asks one decision procedure about every element many times asks
   instead its table, `memo H`, with the theorem `memo H ≐ H`.
+  **Both forms of a definition, the textbook's first**.  Where a notion
   has a textbook definition and a computed one (the number of Sylow
   p-subgroups, and the number of conjugates of P; the index, and |G|/|H|;
   the least subgroup that holds A, and the elements a search reaches),
   the library gives both: the textbook's first, even when it is the
   slower to evaluate, then the computed one, with the theorem that they
   agree.  The reason: the textbook's form is what a reader checks a
   statement against, and the computed form is what evaluates on a
   concrete group; the theorem lets each serve where the other cannot.

## What happens to a pull request

+  **The review**.  The maintainer, William DeMeo, reviews every pull
   request and merges it; a contributor never requests a review on his
   behalf, from him or from a bot.  The checks above must pass.  The
   review then reads each module against the rules of this guide, checks
   each statement against the source it cites, and looks for a
   definition the library or the Agda Universal Algebra Library already
   has under another name.
+  **Authorship**.  The module's front matter names the agda-groups
   development team, and the commit history names you.

### Commits and pull requests

+  Fork the repository, and make a branch for the issue, named after it
   (`12-short-description`).
+  Make each commit one coherent change, with a one-line summary and, for
   a change that is not trivial, a paragraph saying what it does and why.
+  Keep a pull request to one concern, and open it against `main`, with
   `Closes #N` for the issue it addresses.

Ask in the issue or the pull request itself, or open an issue.
